# pic-blog UI E2E 핸드오프

**목적** — 모바일/데스크탑 레이아웃이 의도대로 구현됐는지, 디자인 시스템에서 벗어난 것이
있는지 찾는다. 기능 검증이 아니다 (그건 `scripts/smoke.js` 가 본다).

**대상** — https://pic-blog.jun-devlog.win

```bash
aside repl "await openTab('https://pic-blog.jun-devlog.win/')"   # 결정적 자동화
aside "이 페이지의 레이아웃 문제를 찾아줘"                          # 에이전트 세션
```

---

## 1. 뷰포트

| | 폭 | 비고 |
|---|---|---|
| 모바일 | **390 × 844** | 브레이크포인트는 `max-width: 900px` |
| 데스크탑 | **1440 × 900** | |

경계값 확인이 필요하면 899 / 901 도 본다. **두 폭에서 마크업이 다른 화면이 있다**
(§4 헤더) — 미디어쿼리로 눌러 담은 게 아니라 두 벌을 그려 하나만 보인다.

## 2. 페이지 목록

로그인이 필요한 화면은 게이트(`/editor`)에서 비밀번호를 넣어야 한다.
자동 로그인은 `agent-browser auth login picblog` (자격증명은 볼트에 있다).

| # | URL | 인증 | 상태 만드는 법 |
|---|---|---|---|
| 1 | `/` | — | 공개 기록 목록. 로그인 상태면 비공개도 보인다 |
| 2 | `/p/record-20260414` | — | 공개 기록 상세 (12포인트 29장) |
| 3 | `/p/record-20260414` → 포인트 클릭 | — | **상세 시트** (모바일: 바닥 시트 / 데스크탑: 좌측 패널) |
| 4 | 시트 → 사진 탭 | — | **라이트박스 캐러셀** |
| 5 | `/editor` | ✔ | 기록 관리 목록 |
| 6 | `/editor/new` | ✔ | 업로드 1단계 (사진 선택) |
| 7 | `/editor/record-20260414` | ✔ | 편집 — 1단계 「기록 설정」 |
| 8 | 7 → 「포인트 편집」 탭 | ✔ | 편집 — 2단계 |
| 9 | `/editor/add/record-20260414` | ✔ | 사진 추가 1단계 |
| 10 | `/editor` (로그아웃 상태) | — | 편집 게이트 (비밀번호 화면) |

> 6·9 의 미리보기 단계(지도+반경 슬라이더)는 사진 업로드가 필요해 자동화가 어렵다.
> 필요하면 로컬에서 `_workspace` 밖의 테스트 JPEG 로 재현한다.

## 3. 디자인 시스템 — 이 값들에서 벗어나면 결함이다

### 색 (`app/assets/css/tokens.css`)

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--ink` | `#E8EBE9` | 본문·제목 |
| `--mid` | `#B1C7C1` | 보조 텍스트·버튼 |
| `--acc` | `#92B2A9` | 링크·강조 |
| `--deep` | `#83A79E` | 데이터·캡션 |
| `--faint` | `#6B837E` | 3차 캡션 |
| `--s0` `--s1` `--s2` `--s3` | `#040408` `#0B0E12` `#1E2125` `#2A2A30` | 표면 |
| `--field` | `#101317` | 입력 필드 |
| `--route` | `#FFB454` | **동선 전용 난색.** 팔레트 밖이고 여기 말고는 쓰지 않는다 |
| `--danger` | `#FF8080` | 파괴적 동작 |

**다크 단일 테마다. 라이트 테마는 없다.**

### 타이포

| 토큰 | 얼굴 | 쓰임 |
|---|---|---|
| `--font-display` | Bricolage Grotesque → Pretendard | 제목·수치 강조 |
| `--font-body` | Pretendard | 본문 |
| `--font-mono` | Geist Mono | **데이터** — 좌표·시각·거리·파일명·EXIF |

숫자·좌표·시각이 mono 가 아니면 결함이다. Bricolage 에는 한글 글리프가 없어
한글은 Pretendard 로 떨어진다 — 제목의 한글/라틴이 섞여 보이는 건 정상이다.

### 크기 (`app/assets/css/base.css`, ≤900px)

| 대상 | 값 |
|---|---|
| **헤더 안** 버튼·링크 | **36px** 고정, 내용 두 축 중앙 |
| **헤더 밖** 조작 요소 | **44px** (터치 타깃) |
| 모든 `input` / `textarea` / `select` | **16px 이상** — iOS 가 그 미만이면 페이지를 확대한다 |
| `--radius` / `--radius-lg` | 8px / 10px |

### 버튼 규칙

- **배경이나 테두리가 있어야 한다.** 텍스트만 있는 버튼은 금지.
- 예외: **아이콘 전용**은 상자 없이 ghost 로 둔다 (배경은 눌렀을 때만).
- 오른쪽 정렬, 가장 오른쪽이 주 동작. 파괴적 동작은 시각적으로 분리.

### 포커스

- 자기 테두리가 있는 입력 → `:focus` 에서 border-color + `--focus-ring`
- 테두리 없는 입력 → 감싸는 컨테이너가 `:focus-within` 으로 빛남
- 그 밖 → `outline: 2px solid var(--focus-border)`, offset 2px
- 🔴 **이중 링**(테두리 + outline 이 겹쳐 사각형 두 개)이 보이면 결함
- 🔴 포커스했을 때 **요소 모양이 바뀌면**(둥근 버튼이 각져 보임) 결함

## 4. 레이아웃 의도 — 폭마다 다르게 보이는 게 «정상»인 것들

여기 적힌 차이는 의도한 것이다. 결함으로 올리지 않는다.

| 화면 | 모바일 | 데스크탑 |
|---|---|---|
| 헤더 공통 | `[←] [화면 이름/단계] [부가 메뉴]` | 기존 구조 (배지·상태·펼친 버튼들) |
| `/` | 마크만, 워드마크·정렬 접힘 · **통계는 그대로 보인다** | 마크 + `pic·blog` + 정렬 + 통계 |
| `/editor` | `[←] 기록 관리` · 행 우측 연필 하나 | 브랜드 + 「편집」「보기」 버튼 |
| `/editor/[slug]` | `[←] 타이틀 [⋯]` · 저장은 하단 CTA · 공개 토글은 1단계 | 배지+상태 / 토글·목록·취소·저장 |
| `/p/[slug]` 시트 | 바닥에서 올라오는 시트, 손잡이로 쓸어 닫기 | 좌측 패널 |
| 시트 정보 | **ⓘ 하나**가 시각·좌표·사진수·기기·EXIF·태그·본문을 «한 판»에 | 헤더 메타 + 우측 `.side` 에 제자리 표시 |
| 주 동작 | 하단 고정 CTA | 헤더 우측 |

**모바일에서 헤더에 저장·공개 토글이 보이면 결함이다** — 각각 하단 CTA 와 1단계로 갔다.

## 5. 화면별 점검표

### 공통 (모든 페이지, 두 폭)

- [ ] **가로 스크롤이 없다** — `document.documentElement.scrollWidth <= innerWidth`
- [ ] 콘솔에 error 가 없다
- [ ] 헤더 컨트롤 높이가 전부 같다 (**두 폭 모두 36px**. `role="switch"` 공개 토글만 예외)
- [ ] 텍스트가 잘리거나(`…`) 요소 밖으로 넘치지 않는다
- [ ] 겹쳐 보이는 요소가 없다

### 1. `/` 홈
- [ ] 카드 그리드가 폭에 맞게 재배치된다
- [ ] 모바일: 로고 마크만 · 정렬 접힘 · 통계(`1 기록 · 12 포인트 · 29장`)는 그대로
- [ ] 푸터: `© 2026 · Junjak · ⑂` / github · mail, 아이콘은 상자 없이

### 2·3. `/p/[slug]` 와 상세 시트
- [ ] 지도 위 번호 마커가 라벨 위에 있다
- [ ] **동선이 `--route`(#FFB454) 난색 파선**이다. 어둡거나 세이지면 결함
- [ ] 모바일 시트: 헤더 **한 줄 48px 고정**
- [ ] **ⓘ 를 눌러도 헤더·스캐터가 움직이지 않는다** (레이아웃 고정)
- [ ] ⓘ 는 **하나만** 보인다 (시트가 뜨면 페이지 상단바 ⓘ 는 숨는다)
- [ ] 사진 산포가 겹치되 서로 가리지 않는다

### 4. 라이트박스
- [ ] 캡션이 사진 **바로 아래**에 붙는다 (멀리 떨어져 있으면 결함)
- [ ] 헤더: 파일명 · `n / m` · ✕
- [ ] 좌우 이동 컨트롤이 폭에 맞게 배치된다

### 5. `/editor` 목록
- [ ] 행 전체가 클릭 대상이고 우측에 **연필 하나**
- [ ] 공개 토글이 **없다** (편집 1단계로 갔다)
- [ ] 비공개 기록에 「비공개」 표시
- [ ] 제목이 한 줄 `…` 로 잘리지 않는다 (두 줄까지 흐른다)

### 7·8. `/editor/[slug]`
- [ ] 단계 탭 `1 기록 설정` / `2 포인트 편집 n`
- [ ] 1단계: 타이틀·요약·공개·기간(잠김)·포인트 범위
- [ ] **포인트 범위가 슬라이더**다 (업로드 화면과 같은 컨트롤). 버튼 4개면 결함
- [ ] 하단 CTA 에 「저장」, 그 위로 내용이 가리지 않는다

### 10. 편집 게이트
- [ ] 입력 포커스에 **링이 하나만** 보인다
- [ ] 「편집 시작」이 비어 있어도 비활성이 아니다 (누르면 이유를 말한다)

## 6. 알려진 것 — 결함으로 올리지 않는다

- **iOS 홈 화면 앱 상단 흐림·터치 밴드** — iOS 가 그리는 것이고 CSS 로 못 끈다.
  `--top-inset` 으로 콘텐츠를 내려 대응한다. 브라우저에는 안 나타난다.
- **테스트 사진이 빨강/파랑 색면에 `TOP-LEFT` 글자** — 합성 픽스처다. 운영 기록
  `record-20260414` 만 실제 사진이다.
- 사진이 JPEG 인 것 — iOS Safari 가 canvas WebP 인코딩을 지원하지 않는다.
- 데스크탑 `/editor/[slug]` 가 세로로 조금 스크롤되는 것 — 알려진 사소한 건.

### 크기 규칙의 «의도한» 예외

- **Mapbox 줌 in/out 32×32** — 서드파티가 그리는 지도 크롬이다. 44px 로 키우면 지도 위에
  88px 짜리 덩어리가 생긴다. 손가락으로는 핀치 줌이 주 경로라 그대로 둔다.
- **공개 토글(`role="switch"`)** — 버튼이 아니라 스위치다. 36px 규칙에서 뺀다.
- **정렬(`.sorts`)** — 세그먼티드 컨트롤. 「텍스트만 있는 버튼 금지」는 **묶음 단위**로 지킨다.
  트랙이 테두리·배경을 갖고 낱개 칸은 고른 것만 채워진다. 낱개에 테두리를 두르면
  「하나만 고른다」가 안 읽힌다.
- **편집 게이트 비밀번호 칸** — `input` 자체는 30.5px 지만 감싸는 `<label class="field">`
  가 46px 이고, label 이라 여백을 눌러도 입력이 잡힌다. **유효 타깃은 46px** 이다.
  (태그 입력도 같은 이유로 `<span>` → `<label>` 로 바꿨다.)
- **사진 칸의 ✕** — 보이는 아이콘은 20px 그대로다. 44px 은 «보이지 않는 판»이고
  칸이 `overflow: hidden` 이라 칸 우상단 모서리에 붙여 넣었다. `getBoundingClientRect()` 로 재면
  20px 이 나오는 게 맞다 — `::after` 나 `elementFromPoint` 로 봐야 한다.
- **사진 칸의 ⠿(핸들) 20px** — 여긴 판을 두지 않는다. 칸이 84px 이라 ✕ 의 44px 과 겹치고,
  둘이 합쳐 칸 오른쪽을 통째로 먹어 «끌 자리»가 사라진다. 핸들은 **키보드 전용**이다 —
  터치 재정렬은 칸 자체를 끄는 것이고 핸들은 ←/→ 를 받는 포커스 타깃일 뿐이다.
- **태그 칩 ✕** — 보이는 상자는 24px, 판이 44px. 위와 같다.

## 7. 보고 형식

결함마다 **화면 · 뷰포트 · 무엇이 어긋났는지 · 기대값**을 적는다.

```
/editor · 390 · 행 우측 연필이 40px (헤더 밖 규칙 44px 위반)
/p/[slug] · 1440 · 동선이 어두운 회색 (--route #FFB454 이어야 함)
```

「이상해 보인다」만으로는 못 고친다 — **어느 규칙의 어느 값에서 벗어났는지**를 적는다.
규칙에 없는 문제라면 그렇게 적고 근거(스크린샷·측정값)를 붙인다.
