# 사진 좌표 기준 동선

포인트 반경으로 묶인 사진의 이동이 대표 좌표 하나로 축약되는 문제를 해결한다.
반경·마커·사진 편집은 유지하고, 동선과 거리만 사진 고유 좌표를 촬영 시각순으로 잇는다.

기준 커밋: `44e83bdafe4a5d2b3e4f121b5d53a2c86e0c5ece`.
시작: `2026-10-07T15:00:15Z`.

## 범위와 근거

- `photo.lat/lng/shot_at` 에 원래 값이 이미 저장돼 있어 테이블·열 추가와 데이터 이관은 필요 없다.
- 상세 지도·새 기록 미리보기의 선은 같은 포인트 안의 사진까지 모두 지난다. 뷰포트도 사진 좌표를 포함한다.
- 목록·상세 API 의 `distance_km` 은 같은 촬영 순서로 계산한다. API 형태는 유지한다.
- 같은 시각은 사진 ID 순서다. 촬영 시각이 없는 사진은 기존 정책대로 동선에서 제외한다.
- 운영 DB 실행·배포는 범위 밖이다.

## 수용 기준

1. 한 포인트 안의 왕복이 선과 거리에서 사라지지 않는다.
2. 사진 소속·표시 순서·대표 위치·반경이 바뀌어도 사진이 같으면 동선과 거리가 같다.
3. 사진 추가·삭제는 동선과 거리에 반영된다. 저장된 원본 좌표는 보존된다.
4. 같은 촬영 시각·시각 없는 사진·사진 0~1장의 처리 결과가 결정적이다.

## 검증

`VERIFY_PASS`.

- `pnpm typecheck`: 종료 0.
- `pnpm test`: 25/25 통과. 한 포인트의 왕복·소속이 섞인 촬영 순서·동일 시각·시각 없는 사진·사진 0~1장을 검증했다.
- `pnpm test:e2e tests/e2e/photo-route.spec.ts`: 빌드 종료 0, 1/1 통과. API 생성 → 포인트 합치기·사진 수동 정렬·대표 위치 이동 → 반경 재묶기 → 사진 추가 → 격리 DB 원본 좌표 확인 → 화면 새로고침·목록/상세 거리 확인 → 사진 삭제를 검증했다.
- 지도 실행 확인: 격리 DB 의 공개 포인트 1개에 사진 3장을 담았다. 실제 `trip-route` GeoJSON 은 `[[128.4275,34.8453],[128.4275,34.8473]]` 와 복귀 구간, 총 2개였다. 마커는 1개, 표시 거리 0.4km. 지도 bounds 에 사진 좌표 전체가 들어갔다. 증거: `_workspace/e2e/2026-10-08-photo-route/trip-route.png`.
- 빌드 경고: 기존 `tokens.css` 의 relative-color 계산식 PostCSS 경고와 큰 청크 경고. 토큰 계산식은 기준 커밋에도 동일하다. 이번 변경에 포함하지 않았다.

좌표·사진의 API 공개 범위와 편집 인증을 유지한다. 새 입력 경계·HTML 삽입·비밀정보 추가가 없다.
설계 기준은 연결된 제품 스펙 §3·§6 에 반영했다. 추가 QA 는 별도 요청 후 진행한다.
